HTML5 Semantic Elements Reference

Core HTML5 elements I use to structure documents without relying on generic<div>wrappers:

Semantic Landmarks & Content Elements
Element Category Primary Purpose Best Practice / Accessibility Note
<header> Landmark Introductory content or site-wide branding and navigation Keep primary site navigation inside a top-level header
<nav> Landmark Major blocks of internal or external navigation links Add aria-label when using multiple nav bars on one page
<main> Landmark Dominant, unique content of the document body Use only one visible <main> element per page
<article> Sectioning Self-contained composition that could stand alone (e.g., project card, post) Always include a heading (<h2>–<h6>) inside
<table> Tabular Data Organizing multi-variable data across rows and columns Never use tables for page layout; pair with <thead> and scope

Core Web Concepts (In My Own Words)

Semantic HTML
Writing markup where the tag describes the meaning and role of the content—not how it looks visually. This improves screen-reader navigation, SEO, and code maintainability.
Relative vs. Absolute File Paths
A relative path (like href="stack.html") points to a file based on the current page's location in the project folder, making the entire site portable. An absolute path points to a full external URL.
Separation of Concerns
Keeping structure (HTML), presentation (CSS), and behavior (JavaScript) isolated in their own layers so bugs are easier to isolate and stylesheets can be swapped cleanly.
